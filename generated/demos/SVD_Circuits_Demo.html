SVD Circuits Demo¶

This notebook decomposes one attention head’s QK (\(W_Q W_K^\top\)) and OV (\(W_V W_O\)) weight maps into orthogonal singular directions with FactoredMatrix.svd, reads the OV directions out through the final norm and unembedding with logit_readout, projects the head’s cached output onto them, and measures the effect of retaining or ablating single directions on one IOI prompt’s logit difference with a hook on hook_result. Mathematically distinct directions need not be semantically or causally distinct subfunctions.

Based on Areeb Ahmad, Abhinav Joshi, Ashutosh Modi, “Beyond Components: Singular Vector-Based Interpretability of Transformer Circuits”, arXiv 2511.20273.

1. Decompose a name-mover head¶

Layer 9 head 9 is the canonical name-mover head in GPT-2-small’s indirect-object-identification (IOI) circuit. Two weight maps describe what it does:

  • QK \(= W_Q W_K^\top\) decides which residual-stream directions the head compares when forming its attention pattern.

  • OV \(= W_V W_O\) decides what the head writes back into the residual stream.

Both are \(d_{\text{model}} \times d_{\text{model}}\) but rank at most \(d_{\text{head}} = 64\). FactoredMatrix keeps each map as its two factors and computes the SVD \(M = U \Sigma V^\top\) without ever materialising the \(768 \times 768\) product. The convention matters, because both factors are \(d_{\text{model}}\)-wide and a swap raises no shape error:

  • For OV, the columns of \(V\) are the residual-stream write directions, the ones read out through the unembedding below; the columns of \(U\) span the input the values read.

  • For QK, the columns of \(U\) are the destination (query-side) read directions and the columns of \(V\) the source (key-side) read directions. QK writes nothing, so it has no vocab readout.

On grouped-query models W_K and W_V can carry one row per key/value head, so query head \(h\) reads key/value head \(h\) // (n_heads / n_key_value_heads). head_maps resolves that from the weight shapes, which makes it a no-op on GPT-2.

# NBVAL_IGNORE_OUTPUT
# sigma and sigma/sigma_max are float32 reductions, so the fourth decimal can differ between CPU
# kernels. The report shows which directions are degenerate, not a pinned numeric value.
PROMPT = "When Mary and John went to the store, John gave a drink to"
LAYER, HEAD = 9, 9
EPS = 1e-2  # Neighbouring singular values closer than this, relatively, form one block.


def head_maps(model, layer, head):
    """The head's QK and OV maps as FactoredMatrix objects."""
    attn = model.blocks[layer].attn
    kv_head = head // (attn.W_Q.shape[0] // attn.W_K.shape[0])
    W_Q, W_O = attn.W_Q[head].detach(), attn.W_O[head].detach()
    W_K, W_V = attn.W_K[kv_head].detach(), attn.W_V[kv_head].detach()
    return FactoredMatrix(W_Q, W_K.T), FactoredMatrix(W_V, W_O)


def rank_report(S, eps=EPS):
    """One row per direction; degenerate means inside a near-equal block or numerically null."""
    near = (1 - S[1:] / S[:-1]) < eps
    blocked = torch.cat([near, near.new_zeros(1)]) | torch.cat([near.new_zeros(1), near])
    # The relative tolerance torch.linalg.matrix_rank uses for a d_model x d_model map.
    null = S / S[0] < model.cfg.d_model * torch.finfo(S.dtype).eps
    return [
        {
            "idx": i,
            "sigma": float(S[i]),
            "ratio": float(S[i] / S[0]),
            "degenerate": bool(blocked[i] or null[i]),
            "null": bool(null[i]),
        }
        for i in range(len(S))
    ]


qk, ov = head_maps(model, LAYER, HEAD)
U, S, V = ov.svd()  # U and V are [d_model, d_head]; S is sorted descending.
report = rank_report(S)
eligible_ids = [row["idx"] for row in report if not row["degenerate"]]
display_ids = eligible_ids[:5]

qk_isolated = sum(not row["degenerate"] for row in rank_report(qk.S))
print(f"QK: sigma_max {float(qk.S[0]):.4f}, {qk_isolated} of {len(qk.S)} directions isolated")
print(f"OV: sigma_max {float(S[0]):.4f}, {len(eligible_ids)} of {len(S)} directions isolated")
print()
print(f"{'idx':>4} {'sigma':>10} {'sigma/sigma_max':>16} {'degenerate':>11} {'null':>6}")
for row in report[:12]:

        f"{str(row['degenerate']):>11} {str(row['null']):>6}"

Reading the rank report¶

Singular directions are unique only when the singular values are distinct. Near-equal consecutive singular values define a subspace whose basis is only defined up to a rotation, so individual directions inside such a block are not attributable: “direction 3 is the surname subfunction” would be a statement about an arbitrary basis choice rather than about the model. A block is a run of neighbours each within EPS of the previous one, so a block can span more than EPS end to end. Numerically null directions are arbitrary vectors from the map’s null space and are equally unusable.

The rest of the notebook therefore reads, projects and patches only isolated, non-null directions. A complete degenerate block can still be retained or removed as a subspace; only splitting it is meaningless.

2. Vocab projections of eligible directions¶

logit_readout reads any \(d_{\text{model}}\) vector through the model’s final norm and unembedding. Two adjustments make that a readout of a direction:

  • Singular vectors are defined only up to sign: flipping a column of \(U\) and the matching column of \(V\) leaves the map unchanged. Both ends of each direction are shown.

  • The readout of the zero vector is the part of the final norm and unembedding that does not depend on the input (the folded final-norm bias). Subtracting it leaves logits that flip sign with the direction.

[4]:

# NBVAL_IGNORE_OUTPUT
# Token rankings can change across kernels when float32 projection magnitudes nearly tie.
def read_directions(directions):
    """Vocab logits of [k, d_model] directions, less the input-independent offset."""
    zero = torch.zeros_like(directions[:1])
    return logit_readout(model, directions).values - logit_readout(model, zero).values


def decode(ids):
    return [model.tokenizer.decode([int(token)]) for token in ids]


readout = read_directions(V[:, display_ids].T)
for idx, logits in zip(display_ids, readout):

3. Activation projections on a prompt¶

With use_attn_result on, blocks.9.attn.hook_result holds each head’s output separately, shaped [batch, pos, head, d_model]. Caching only that hook and projecting head 9’s slice onto \(V\) gives the coefficient of every write direction at every position. The sign of a coefficient follows the arbitrary sign of its direction, so magnitudes are shown.

4. Intervention comparisons¶

A hook on hook_result replaces head 9’s output \(r\) at every position with its image under a projector and leaves every other head untouched:

  • keep direction \(i\): \(r \mapsto (r \cdot v_i)\, v_i\), retaining only that direction;

  • ablate direction \(i\): \(r \mapsto r - (r \cdot v_i)\, v_i\), removing it.

Each run reports delta, the change in the logit difference " Mary" minus " John" at the final position, which includes all downstream computation. As a reference, the same intervention is applied along 32 random unit directions drawn inside the head’s own OV span, so a control is an arbitrary direction of this head’s output rather than of the whole residual stream. share is the fraction of those controls whose |delta| is smaller than the direction’s own:

  • In keep mode, a low share means retaining the direction moves the metric less than most random in-span directions do.

  • In ablate mode, a high share means removing it moves the metric more than most random in-span directions do.

These are comparisons with a small sample of controls on one prompt, not significance tests. The whole-head ablation first gives context: it zeros the head’s output, which a same-width control cannot distinguish from itself.

[6]:

# NBVAL_IGNORE_OUTPUT
# The deltas are float32 reductions, and a value sitting on a rounding boundary can print one
# digit apart across CPU kernels.
mary, john = model.to_single_token(" Mary"), model.to_single_token(" John")
identity = torch.eye(model.cfg.d_model, device=V.device)


def logit_diff(logits):
    return float(logits[0, -1, mary] - logits[0, -1, john])


def patched_logit_diff(projector):
    """Logit difference with the head's output replaced by its image under projector."""

    def hook(result, hook):
        result = result.clone()
        result[:, :, HEAD] = result[:, :, HEAD] @ projector
        return result

    return logit_diff(model.run_with_hooks(PROMPT, fwd_hooks=[(hook_name, hook)]))


def keep(v):
    return torch.outer(v, v)


def ablate(v):
    return identity - torch.outer(v, v)


original = logit_diff(model(PROMPT))
print(f"original logit difference: {original:.3f}")
print(f"whole-head ablation delta: {patched_logit_diff(0 * identity) - original:+.3f}")

N_CONTROLS = 32
rank = sum(not row["null"] for row in report)
draws = torch.randn(rank, N_CONTROLS, generator=torch.Generator().manual_seed(0)).to(V.device)
controls = V[:, :rank] @ torch.nn.functional.normalize(draws, dim=0)

5. What this does and does not show¶

This example decomposes one GPT-2-small head and measures prompt-specific effects of retaining or ablating eligible OV directions, next to random in-span controls. It does not establish named subfunctions, statistical separation from arbitrary directions, or replication of the paper’s causal subfunction taxonomy.

  • Single head, single model, single prompt. Everything above concerns layer 9 head 9 of gpt2-small on one IOI prompt. Nothing here assembles a multi-head circuit.

  • Descriptive projections. Orthogonal weight-space directions are mathematically distinct; vocab readouts and activation coefficients do not supply semantic labels.

  • Comparisons, not significance. The tables report metric changes and how they sit among 32 random controls, not confidence bounds. They do not establish that any direction is distinguishable from an arbitrary one.

  • Downstream responses. Every delta measures the final logit difference after downstream computation, not the head’s direct write contribution. A small final-logit effect need not imply a small direct contribution, and these measurements do not identify a compensating component.

  • Repeatability, not confirmation. Shares near the middle can change with the seed or the number of controls. Fixing the seed makes the comparison repeatable, not scientifically conclusive.

Using this on other models¶

  • The layer must hold an attention block with W_Q, W_K, W_V and W_O. SSM, mixer, linear-attention and AltUp layers, and encoder-decoder bridges without a blocks stack, have no such head to decompose.

  • Sections 3 and 4 need per-head outputs: set_use_attn_result(True) raises NotImplementedError on attention bridges that cannot split their output by head. Check that hook_result actually appears in the cache before trusting a patch, since a patch on a hook that never fires changes nothing.

  • Decompose, read out and patch under one weight-processing state. The weights, the final norm and hook_result all change when compatibility mode folds and centers them, so a decomposition taken before enable_compatibility_mode() does not describe the model afterwards.

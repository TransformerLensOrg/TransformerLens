1"""Attribution patching — linearized activation patching on ``TransformerBridge``. 

2 

3Attribution patching estimates the causal effect of every model component on a 

4task metric with a *gradient-based linearization* of activation patching: rather 

5than one forward pass per intervention, it reads a single gradient cache. For a 

6clean/corrupt prompt pair it runs a clean forward (for ``a_clean``) and a corrupt 

7forward whose backward hooks capture ``g = d(metric)/d(a)`` (for ``a_corrupt`` and 

8its gradient), and scores each node with the 

9first-order Taylor estimate ``effect(node) = (a_clean - a_corrupt) . g``. Scores 

10over a batch of clean/corrupt pairs are averaged before ranking. 

11 

12Only the ``TransformerBridge`` API is targeted; TransformerLens v4 deprecates 

13``HookedTransformer``. 

14 

15Sign/direction convention (denoising form): the gradient is taken on the 

16*corrupt* run and the estimate points *toward* the clean activation, so a 

17positive score means patching that node from corrupt toward clean moves the 

18metric in the positive direction. An oracle-parity test maps this convention 

19onto a pinned reference rather than assuming the two agree. 

20 

21Memory note: gradients are retained only for hook points passing ``names_filter``. 

22Retaining gradients at every hook point roughly doubles cache memory, so callers 

23should filter to the hook families their analysis actually reads. 

24 

25Scope: this build ships node granularity with plain attribution (``ig_steps=1``). 

26Edge scoring (EAP), the integrated-gradient path (EAP-IG, ``ig_steps>1``), and 

27ablate-outside faithfulness are not implemented yet; their API is declared here — 

28``granularity="edge"`` and ``ig_steps>1`` raise :class:`NotImplementedError` — so 

29downstream code can pin against a stable surface now. 

30"""

116 """Configuration for an attribution-patching sweep. 

117 

118 The two axes are deliberately orthogonal: 

119 

120 - ``granularity`` selects what is scored: ``"node"`` scores each residual-stream 

121 write, ``"edge"`` scores each ``(source, destination)`` write->read pair. 

122 - ``ig_steps`` selects gradient fidelity. ``ig_steps=1`` is plain attribution 

123 patching / EAP: a single first-order Taylor gradient taken at the corrupt 

124 point. ``ig_steps>1`` is EAP-IG: the integrated gradient averaged over that 

125 many points along the corrupt->clean path, which corrects the gradient 

126 saturation that makes plain attribution unfaithful. 

127

129 ``method`` enum (``"attribution"``/``"EAP"``/``"EAP-IG"``) and ``ig_steps``,

183 def top_nodes(self, k: int = 10) -> list[tuple[Node, float]]:

274 grad-enabled forward, then drives a single backward with 

275 :func:`torch.autograd.grad` to fire the backward hooks. 

276 ``run_with_cache(..., incl_bwd=True)`` only backpropagates the model's own 

277 scalar output, so a custom (non-scalar-output) metric such as a logit-diff 

278 needs the backward driven here. 

279 

280 Gradients come from the backward hooks, not from ``.grad`` on the cached 

281 tensors. ``TransformerBridge`` reshapes the tensor handed to a forward hook at 

282 a converted point (``attn.hook_z``, ``hook_q/k/v``, ``hook_attn_out``), so that 

283 tensor is a view the model's forward never consumes: ``retain_grad()`` on it is

288 model-sized buffer allocated.

438def attribution_patch( 

439 model: Any, 

440 clean: torch.Tensor, 

441 corrupt: torch.Tensor, 

442 metric_fn: MetricFn, 

443 config: EdgeAttributionConfig = EdgeAttributionConfig(), 

444) -> AttributionResult: 

445 """Estimate every node's causal effect on ``metric_fn`` in two forwards + one backward. 

446 

447 For each clean/corrupt pair this runs a clean forward (for ``a_clean``) and a 

448 corrupt forward whose backward hooks capture ``g = d(metric)/d(a)`` (for 

449 ``a_corrupt`` and its gradient), then scores each node with the 

450 first-order Taylor estimate ``effect(node) = (a_clean - a_corrupt) . g``. 

451 

452 Sign/direction convention (denoising form): gradients are taken on the *corrupt* 

453 run and the estimate points *toward* the clean activation, so a positive score 

454 means patching that node from corrupt toward clean moves the metric in the 

455 positive direction. An oracle-parity test maps this convention onto a pinned 

456 reference rather than assuming the two agree. 

457 

458 Dataset averaging: ``clean``/``corrupt`` may hold a batch of prompt pairs. Each 

459 pair is scored independently (per-example forward/backward, so its own 

460 reconstruction identity holds) and per-node scores are averaged across the batch 

461 before ranking. 

462 

463 Args: 

464 model: A ``TransformerBridge`` (or compatible) exposing ``cfg.n_layers``, 

465 ``hook_dict``, and ``hooks()``. 

466 clean: Clean token ids, shape ``[batch, seq]``. 

467 corrupt: Corrupt token ids, shape ``[batch, seq]``, paired row-by-row with 

468 ``clean``. 

469 metric_fn: Maps single-example logits to a scalar to differentiate. 

470 config: Sweep configuration. This PR supports node granularity with plain 

471 attribution (``ig_steps=1``) only; other values raise at construction. 

472 

473 Returns: 

474 An :class:`AttributionResult` whose ``node_scores`` are averaged over the 

475 batch. ``edge_scores`` stays empty until edge scoring lands. 

476 

477 Raises: 

478 ValueError: if ``clean``/``corrupt`` are not 2D, hold a different number of 

479 pairs, or a pair tokenizes to different lengths (activations must align 

480 position-by-position).
